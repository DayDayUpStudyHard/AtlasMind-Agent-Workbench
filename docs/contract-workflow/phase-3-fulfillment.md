# 三期：履约跟踪与归档（草案）

> 版本：v0.1（草案，未定稿）
> 日期：2026-10-29
> 状态：**草案** —— 强依赖第 1 层（账本归一）；待 3 个业务问题答复
> 对应层：**第 1 层**（业务对象归一：timeline → obligation）
> 阶段枚举见 [README §4](./README.md)

---

## 1. 为什么需要这一期

合同签完就没人管，是目前业务价值损失最大的地方，而系统里有两套互不相通的"义务"：

| 数据 | 谁写 | 谁读 |
| --- | --- | --- |
| `contract_timeline_node` | AI 生成的履约日程 | 履约核验、案件详情 |
| `contract_obligation` | 只有一处手写 `INSERT`（`ContractCaseServiceImpl.java:1868`） | 驾驶舱 KPI（`portfolio.obligations*`） |

结果是：驾驶舱的"履约义务 / 已逾期 / 7 天内到期"长期为 0，而 AI 明明已经抽出了日程。

**不先做归一，三期做出来就是又一个假页面。** 这就是把第 1 层放在三期前置的原因。

## 2. 目标

把"合同签完没人管"变成"每条义务有人跟、有证据、有结论、到期有提醒"。

## 3. 前置：第 1 层账本归一（三期必须先做完）

要点（细节待第 1 层单独立稿）：

1. **唯一账本**：以 `contract_obligation` 为准，AI 生成的日程节点转为义务记录（带 `source` 与来源引用）。
2. **来源标记**：`AI_TIMELINE` / `MANUAL`，保留可追溯的原节点 id。
3. **历史回填**：现有案件按需回填一次，回填结果标"系统导入"，不改人工已确认内容。
4. **切换策略**：驾驶舱 KPI 改读归一后的账本；旧查询路径保留一个版本周期，便于回滚。

## 4. 范围

| 做 | 不做 |
| --- | --- |
| 义务台账页（来源 / 责任人 / 到期 / 状态 / 证据） | 发票、ERP、合同系统的**实际对接** |
| 履约核验结果挂到对应义务 | 短信 / 邮件 / 企微等提醒渠道 |
| 证据上传与来源枚举（`MANUAL` 启用，其余预留） | 自动续签决策 |
| 归档 / 续签动作（新建或开新周期，待定） | 义务的自动催办规则引擎 |

## 5. 待决问题

| # | 问题 | 建议默认值 |
| --- | --- | --- |
| 1 | **财务角色是否单列**：付款类义务的证据确认由业务负责人还是财务 | 先由业务负责人，财务二期再说 |
| 2 | **多方合同**：担保方 / 代理方是否需要独立签字 | 一期不拆，按主合同处理 |
| 3 | **续签**：新建案件还是同案件开新周期 | 新建案件，保留关联 id |
| 4 | **证据来源**：除人工上传外，先接哪个系统 | 都不接，只留字段 |

## 6. 设计要点（草案）

### 6.1 证据来源

| 值 | 一期 | 说明 |
| --- | --- | --- |
| `MANUAL` | 启用 | 人工上传，走现有解析链路 |
| `INVOICE` | 预留 | 发票号、开票日期、金额校验 |
| `ERP` | 预留 | 单据号与金额比对 |
| `CONTRACT_SYSTEM` | 预留 | 签署 / 变更状态回传 |

要求：证据记录必须有 `source` 与 `external_ref`，UI 上区分"人工上传 / 系统回传"，避免审计混淆。

### 6.2 义务台账页

- 列表：义务描述 / 来源 / 责任人 / 到期日 / 状态（待履行 / 逾期 / 已完成 / 已豁免）。
- 单条展开：原文引用、证据列表、核验结论、操作历史。
- 逾期与 7 天内到期高亮；**不伪造数据**，没证据就显示"待补证"。

### 6.3 归档 / 续签

- 归档前置：全部义务有终态，或合同已到期且有终态决议。
- 归档后案件只读；续签生成新案件并关联原案件。

## 7. 验收雏形

1. AI 生成日程后，义务台账里出现对应义务，且能追溯到原节点。
2. 人工新增的义务与 AI 生成的义务在同一列表，来源可区分。
3. 驾驶舱 KPI 与实际台账一致（不再是 0 或凭空数字）。
4. 上传证据后，义务状态可推进到"已完成"；无证据时不能标完成。
5. 到期/逾期状态按时间自动变化，且与列表筛选一致。
6. 归档后案件不可编辑，续签生成的新案件能回链。

## 8. 风险

- **跳过归一直接做页面** → 又造一个假 KPI，且两套数据继续分叉。
- **历史数据回填** → 需明确"回填只补不改"，否则会覆盖人工确认结果。
- **提醒** → 不在本期范围，但页面必须有"到期"可视，否则用户仍靠记忆。
