## 1. 设计目标与不做什么

**目标**

1. 用户在合同详情页一眼看出：现在到哪一步、在谁手里、我能不能点
2. 所有动作（改、批、打回、撤回、取消、agent 运行）在时间轴上可追溯
3. 每个按钮的**禁用都有原因**，不出现"点不了也不知道为什么"

**不做**

- 不做拖拽编排、不做流程设计器（节点链是固定的）
- 不做实时协同（多人同时看，靠轮询 + 乐观更新）
- 不做移动端专门适配（沿用现有响应式断点 768 / 375）

## 3. 节点条（`FlowNodeBar.vue`）

| 属性 | 规则 |
| --- | --- |
| 段数 | 固定 4 段：上传人 / 部门审批 / 法务 / 签署 |
| 段状态 | `DONE`（实心绿）/ `ACTIVE`（蓝环，含持有者名）/ `BLOCKED`（橙，含失败原因）/ `PENDING`（空心灰）/ `VOID`（斜纹灰，仅在被打回后短暂出现） |
| 打回表现 | 被打回时，从目标段到当前段之间画一条**虚线回退箭头**，并在箭头旁写「张三 打回」 |
| 点击 | 点击某段 → 时间轴自动滚动到该段首次进入的事件 |
| 空态 | 无 flow 的案件显示单行：「历史案件，无流程记录」 |

| 签署（上传人） | 上传签署件 | 当前节点是签署 |
| 法务 | 签署核准 | 存在待裁定的核对结果 |

## 5. 审批面板（`FlowActionPanel.vue`）

### 5.1 通过

- 弹窗标题：`通过 · {节点名}`
- 内容：可选意见（≤ 500 字）+ 提示「通过后内容将被锁定，修改需申请撤回」
- 按钮：`确认通过`（主）/ `取消`

### 5.2 打回

- 标题：`打回 · 打回到哪个节点`
- 必填：**目标节点**（下拉，仅列出当前节点之前的所有节点）+ **理由**（≥ 10 字）
- 提示：「打回后，被打回的节点及其后续节点将重新开始」
- 按钮：`确认打回`（危险色）/ `取消`

### 5.3 申请撤回

- 标题：`申请撤回`
- 必填：理由（≥ 10 字）；只读展示目标节点（= 我的节点）
- 提示：「需当前持有人 {姓名} 批准后，流程将回到你的节点重新开始」
- 若申请人就是当前持有者：提示「你将无法自己批准，申请将转交管理员」

### 5.4 撤回审批（持有者视角）

- 卡片内联展示：`{申请人} 申请撤回：{理由}` + `［批准］［驳回］`
- 驳回必填理由

## 6. 签署件核对（`SignCheckPanel.vue`）

```text
签署件：contract_20261030_signed.pdf   ［重新上传］
─────────────────────────────────────
规则核对
  哈希        ✗ 不一致
  页数        12 → 12        ✓
  条款编号    缺少：第 8.2 条   ✗
  关键字段    金额 500,000 → 450,000  ✗
  相似度      97.3%            ⚠
─────────────────────────────────────
Agent 提示（仅提示，不判定）
  · 第 8.2 条新增「责任上限不超过合同总额 10%」
  · 第 5.1 条「应当」改为「可以」
─────────────────────────────────────
结论：不一致，需处理
［重走审批］  ［放弃本次签署］
```

- 规则项每行三态：`✓ / ✗ / ⚠`，失败行显示 expected → actual
- 「重走审批」二次确认：「将开启新一轮审批，本轮记录保留」
- 「放弃」二次确认：「本轮流程将结束，案件保留」

| `SIGN_DECISION` | ⚖ | 中性 | 签署核对结论：{重走/放弃} |

### 7.2 按轮次分组

撤回批准会**开新一轮**，所以时间轴不是一条直线，而是分段的：

```text
────── 第 1 轮 ──────
 · 09:10 上传 v1
 · 09:40 张三 通过
 · 10:02 李四 申请撤回：金额写错
 · 10:15 李四 批准撤回（李四 = 法务持有者）
────── 第 2 轮 · 撤回重走 ──────
 · 10:16 上传 v2
 · 10:16 Agent 重新运行（触发原因：撤回）
 · ...
```

- 每轮以分隔条开头，标题 `第 {n} 轮`，撤回重走的标注 `· 撤回重走`
- 默认展开**最新一轮**，历史轮次折叠为一行可点开
- 已取消的轮次标题加删除线，并显示取消原因

### 7.3 条目结构

```text
[图标] 标题                                  10:21
       副标题：执行人 · 节点名
       ［展开 ▾］→ payload 明细（JSON 友好化：字段前后值、理由全文）
```

- 同一分钟内同一人的连续同类事件（如多次 `EDIT`）**合并为一条**，显示 `修改了 3 次`，展开后逐条列出
- 打回事件默认展开理由（不截断）
- agent 事件可点「查看运行详情」跳转现有运行详情页

### 7.4 里程碑刻度

- 8 个阶段作为**分组头**插在轴上：进入该阶段的第一条事件上方显示 `③ 要素确认`
- ⑦ 履约 / ⑧ 归档 在二期无事件来源，显示为灰色未激活刻度，鼠标悬浮提示「由案件状态跟踪，暂未纳入流程」

### 7.5 分页与过滤

- 首屏 10 条 + 「加载更多」（每次 50 条，游标翻页）
- 过滤下拉：`全部 / 我的操作 / 审批 / Agent / 修改`
- 过滤只影响前端已加载数据；加载更多继续按原顺序取

## 9. 状态矩阵（核心）

**行 = 身份，列 = 当前节点。** 单元格含义：`可看 / 可操作`。

### 9.1 可见性

| 身份 | 上传人 | Agent | 部门审批 | 法务 | 签署 |
| --- | --- | --- | --- | --- | --- |
| 上传人本人 | 全 | 全 | 只读 | 只读 | 全 |
| 部门审批人（候选） | 只读 | 只读 | 全 | 只读 | 只读 |
| 部门审批人（认领） | 只读 | 只读 | 全 | 只读 | 只读 |
| 法务（候选） | 只读 | 只读 | 只读 | 全 | 只读 |
| 法务（认领） | 只读 | 只读 | 只读 | 全 | 只读 |
| 无关成员 | 只读 | 只读 | 只读 | 只读 | 只读 |
| 管理员 | 全 | 全 | 全 | 全 | 全 |

「只读」= 能看到时间轴与内容，按钮全部置灰并给原因；「全」= 可按 §4.2 操作。

**时间轴可见性（2026-10-30 定）**：对有该案件访问权的成员可见，参与人可操作。若后续要求"仅参与者可见时间轴"，只改后端 `ContractAccessPolicy` 一处，前端不用动。

### 9.2 可操作性

| 动作 | 谁能做 | 前提 |
| --- | --- | --- |
| 认领 | 候选组成员 | 节点待认领，且我没有在该流程其他节点持有 |
| 通过 | 认领人 | 状态 = 处理中 |
| 打回 | 认领人 | 状态 = 处理中，且存在前序节点 |
| 申请撤回 | 任意参与者 | flow RUNNING 且已过上传人节点 |
| 批准/驳回撤回 | 当前持有者 | 申请人 ≠ 我 |
| 取消 | 任意参与者 | 6h 待认领 或 agent 失败 |
| 上传签署件 | 上传人 | 当前节点 = 签署 |
| 签署核准 | 法务 | 存在未裁定核对结果 |
| 修改内容 | 上传人 | 未进入部门审批，或已批准撤回 |

## 10. 空态 / 异常态 / 加载态

| 场景 | 显示 |
| --- | --- |
| 无 flow（历史案件） | 节点条单行「历史案件，无流程记录」，时间轴空态 |
| 候选组为空 | 提交按钮置灰：「该部门尚未配置审批人，请联系管理员」 |
| 节点被他人认领 | 认领按钮变「张三 处理中」，点击提示「请等待或联系他放回」 |
| agent 失败 | 橙色横幅 + 「重试运行」+ 「取消流程」 |
| 撤回待批 | 顶部黄色条：「{申请人} 申请撤回，等待 {持有者} 处理」 |
| 流程已取消 | 全页只读 + 灰条「本轮已取消」+ 「重新上传新版本」 |
| 加载中 | 节点条骨架屏（保持高度，避免跳动） |
| 请求失败 | 内联错误条 + 「重试」，不整页白屏 |

## 11. 刷新与实时

| 数据 | 策略 |
| --- | --- |
| 当前节点 / 持有者 | 轮询 10s；窗口不可见时暂停 |
| 时间轴 | 进入页面加载一次；提供「刷新」按钮；不自动轮询 |
| 认领 / 通过 / 打回 | 成功后**乐观更新**当前节点，再拉一次确认 |
| 冲突（409） | 提示「该节点已被 {姓名} 处理」，自动刷新 |

## 12. 文案规范

| 场景 | 文案 |
| --- | --- |
| 提交置灰 | 「请先确认合同要素和履约日程」 |
| 取消置灰（有认领人） | 「当前有认领人正在处理，不能取消」 |
| 取消置灰（未满 6h） | 「待认领未满 6 小时，还差 {x} 小时 {y} 分」 |
| 候选组为空 | 「该部门尚未配置审批人，请联系管理员配置」 |
| 通过确认 | 「通过后内容将被锁定，后续修改需申请撤回」 |
| 打回确认 | 「将回到 {目标节点}，其后的审批需要重新进行」 |
| 撤回申请 | 「需 {持有者} 批准后才能修改」 |
| 签署不一致 | 「签署件与审批版本不一致，请选择重走审批或放弃」 |
| 网络失败 | 「操作失败，请重试」 |

## 13. 前端验收

1. 四个节点段的状态、持有者、剩余时间正确显示
2. 非持有者看不到「通过/打回」按钮（不是置灰，是不渲染）
3. 取消按钮在两种条件下分别可点/置灰，置灰时能看到具体原因与剩余时间
4. 打回后，节点条出现回退虚线与理由
5. 时间轴能显示 8 类动作，`EDIT` 与 `RETURN` 可展开看明细
6. 签署核对页三态（✓/✗/⚠）与 expected → actual 正确
7. 无 flow 的历史案件不报错
8. 关闭 `flow_v2_enabled` 后回退到旧 `WorkflowStrip`，无白屏
