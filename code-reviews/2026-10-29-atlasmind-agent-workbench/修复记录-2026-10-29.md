## 一、逐项修复明细

### C1. [Critical] 命令注入 + 子进程无超时（MinerU 解析）

- **文件**：`tools/chat-assistant/backend/app/services/mineru_service.py`、`app/config.py`
- **问题**：`{input}/{output}` 直接拼入 shell 命令串后以 `shell=True` 执行，上传文件名含 `;`、`|`、`&&`、`$(...)` 即可注入命令；`timeout=None` 导致 MinerU 挂死时永久占用请求。
- **修复**：
  - 对 `pdf_path` / `job_dir` 使用 `shlex.quote()` 后再格式化进 `MINERU_COMMAND` 模板（保留现有 shell 模板配置方式，不破坏已有部署）。
  - 新增配置 `MINERU_TIMEOUT_SECONDS`（默认 1800 秒），`subprocess.run` 传入该超时；捕获 `TimeoutExpired` 转为可读的 `RuntimeError`。
  - 调整 try 结构，保证超时分支同样会执行 `finally: shutil.rmtree(job_dir)` 清理临时目录。
- **验证**：`python -m py_compile` 通过；静态确认原有异常分支（非 0 返回码、无 Markdown 产物）逻辑不变。

### C2. [Critical] 评测把运行时崩溃当成"跳过"，失败用例计为通过

- **文件**：`tools/chat-assistant/backend/app/api/routes.py`（`_run_evaluation_background`，约 4886 行）
- **问题**：`except ValueError` 将运行时 `ValueError`（pydantic 校验失败、JSON/数值解析失败等）写成 `{"skipped": true}` 后 `continue`，随后仍用空 artifact 打分并执行 `success_count += 1`，崩溃用例被统计为通过。
- **修复**：删除跳过分支；`ValueError` 记录 warning 后 `raise`，交由外层统一按失败用例收口（外层会将 `success=False`、`analysisMode=FAILED` 落库并结束对应 agent_run）。`EvalCaseConfigurationError`（`ValueError` 子类）仍按原逻辑整单失败。
- **验证**：
  - `python -m py_compile` 通过。
  - 静态确认 `case_key`、`eval_run_id`、`task_type` 均在作用域内。
  - 全仓检索确认无其他代码依赖 `stage_outputs` 中的 `"skipped"` 标记（唯一同名命中为无关的重算汇总字段）。
  - 上游 legacy 引擎"不支持任务类型"已在 2321-2334 行统一失败收口，不依赖该跳过分支。

### C3. [Critical] Redis 缓存启用"全放行"默认类型信息，可致反序列化 RCE

- **文件**：`agent-server/src/main/java/com/atlasmind/config/CacheConfig.java`
- **问题**：`activateDefaultTyping(mapper.getPolymorphicTypeValidator(), ...)` 使用的是默认 `LaissezFaireSubTypeValidator`（全放行），Redis value 中的 `@class` 可实例化任意类；第 30 行注释"禁用类型信息"与实现相反。
- **修复**：改用 `BasicPolymorphicTypeValidator` 白名单（`com.atlasmind.`、`java.util.`、`java.time.`），并修正注释。
- **验证**：
  - 静态确认 Spring Boot 3.2.5 对应 Jackson 2.15.x，`BasicPolymorphicTypeValidator`（Jackson 2.10+）可用，导入路径 `com.fasterxml.jackson.databind.jsontype` 正确。
  - 全仓检索：项目实际缓存走 `CacheShieldAspect` + `RedisConfig` 的 `RedisTemplate`；`RedisConfig` 未启用 default typing，不存在同款漏洞，无需改动。
  - 当前代码库无 `@Cacheable/@CacheEvict/@CachePut` 实际使用点，CacheManager 无存量数据，白名单调整不会破坏已有缓存。

### H4. [High] 超时分支引用不存在的 `self.trace_store`

- **文件**：`tools/chat-assistant/backend/app/agent_runtime/runner.py`（`RunDispatcher.dispatch`，约 1334 行）
- **问题**：`RunDispatcher.__init__` 未设置 `trace_store`，超时分支 `await self.trace_store.append_trace(...)` 必然抛 `AttributeError`，HARNESS_TIMEOUT 追踪永远落不了库。
- **修复**：改为 `self.runner.trace_store.append_trace(...)`。
- **验证**：静态确认 `AgentRunner.__init__` 已设置 `self.trace_store`（runner.py:96），且 `RunDispatcher` 在 routes.py:149/195 均由真实 `AgentRunner` 构造。

### H5. [High] 失败落库用 f-string 拼 JSON，且异常被 `pass` 吞掉

- **文件**：`tools/chat-assistant/backend/app/api/routes.py`（`_fail_eval_run`，约 1979-1991 行）
- **问题**：`f'{{"error": "{error}"}}'` 在错误信息含引号/反斜杠/换行时生成非法 JSON；外层 `except Exception: pass` 让写库失败完全无声，评测运行可能永远停在 RUNNING/QUEUED。
- **修复**：改用同文件已有的 `_json_safe({"error": error})`（`json.dumps(..., ensure_ascii=False, default=str)`）；异常分支改为 `logger.exception(...)`。
- **验证**：`python -m py_compile` 通过；静态确认 `_json_safe` 与 `logger` 均在模块内可用（模块级解析，调用时已定义）。

### H6. [High] SSE 流式写入非响应式对象，增量内容不实时渲染

- **文件**：`agent-front/src/components/ChatWindow.vue`
- **问题**：`assistantMsg` 是普通对象，push 进 `ref` 数组后仍通过原始对象执行 `content +=`，绕过 Proxy 不触发依赖追踪；流式输出只能在 `streamingStatus`/`streaming` 变化时被动重绘（打字机效果丢失、结束时一次性显示）。
- **修复**：`const assistantMsg = reactive({ ... })`，并在 import 中引入 `reactive`。
- **验证**：静态确认所有写入点（chunk/error/网络错误/sources/traceId，第 406-418 行）均经过该响应式代理；`history` 组装读取代理属性不受影响。

### H16. [High] 后台接口无鉴权缺陷被 xfail 永久粉饰

- **文件**：`api-tests/test_admin.py`、`api-tests/pytest.ini`
- **问题**：唯一"未登录不得访问 /api/admin/**"用例整体 `xfail`，断言允许 200，且未开 `xfail_strict`。核实发现所述 BUG 当前已不存在（Sa-Token 已拦截），用例实际处于 XPASS，标记成为掩盖"已修复"的过时标记。
- **修复**：移除 `@pytest.mark.xfail`；断言收紧为 `status_code in [401, 403]` 且体 `code != 200`；`pytest.ini` 增加 `xfail_strict = true` 防止同类标记再次把缺陷洗绿。
- **验证**：
  - `python -m py_compile` 通过。
  - 静态确认 `SaTokenConfig` 对 `/api/admin/**` 注册 `SaInterceptor`（`checkActiveLogin` + `ADMIN` 角色），`GlobalExceptionHandler` 将 `NotLoginException`→HTTP 401/code 401、`NotRoleException`/`NotPermissionException`→HTTP 403，断言与实际行为一致。
